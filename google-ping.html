Log

Why is the HTTP status “opaque / 0” for some checks?

Your browser's security model (CORS) only lets a page read a response body and status code from servers that explicitly opt in with an Access-Control-Allow-Origin header. google.com doesn't send that for normal pages, so a plain fetch() to it would show a fake “failed” even on a perfect connection.

So this tool uses checks that are valid from a browser:

  • DNS-over-HTTPS — dns.google/resolve does allow CORS, so you get a real HTTP status code (200) and a real JSON body from Google infrastructure.
  • 204 beacon — google.com/generate_204 requested in no-cors mode. The response is “opaque” (status hidden), but if it resolves, the request genuinely reached Google's edge and Google answered.
  • Image beacon — loads google.com/favicon.ico. Images aren't subject to CORS for display, so onload proves the file came back from Google.

If all three fail together, the connection really is down (or a firewall/proxy/VPN is blocking Google). A single failure is usually a hiccup — hit Ping again.
